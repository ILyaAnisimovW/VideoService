## Как переносить в существующий репозиторий

Скопировать `docs/` и `scripts/`. Корневой README использовать как образец: перенести навигацию и обзорную схему в существующий README, сохранив инструкции запуска проекта.

Mermaid отображается в Markdown на GitHub и в поддерживающих его версиях GitLab. Если версия GitLab или доступный renderer не поддерживает нужную диаграмму, экспортировать SVG и оставить Mermaid как исходник.

Коммитить Markdown, DSL, YAML и JSON как исходники. Картинки C4 при желании экспортировать в `docs/architecture/images/` и встраивать через относительные ссылки. Не коммитить временные файлы рендеринга и секреты.

## Как поддерживать актуальность

- Изменение endpoint: OpenAPI, примеры и связанный сценарий меняются в том же PR.
- Изменение таблицы: ERD, инварианты и миграция меняются в том же PR.
- Изменение взаимодействия: сценарий, DSL и контракт события меняются вместе.
- README содержит карту проекта. Подробные правила живут в соответствующих документах.
- Не добавлять бейджи coverage, uptime или passed до реальных измерений и CI.
