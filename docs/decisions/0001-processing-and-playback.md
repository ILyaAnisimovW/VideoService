# ADR-0001. Асинхронная обработка и приватный HLS

Статус: Proposed. Дата: 2026-10-05.

## Проблема

Обработка видео длительная, загрузка может прерываться, сообщения повторяются. Приватный HLS требует защиты всех связанных ресурсов, а не только master playlist.

## Выбор

Модульный Spring Boot API владеет состоянием и SQL-транзакциями. Отдельный worker получает job из RabbitMQ, claim/lease через внутренний API и scoped доступ к media storage. Job и outbox сохраняются атомарно; result consumer идемпотентен и проверяет job/version/attempt/lease.

Браузер отправляет multipart parts прямо в storage. Для просмотра API выдаёт playback session, читает и переписывает HLS manifests; media segments отдаются storage по коротким signed URL. Полные видео через API не проксируются.

## Альтернативы

| Вариант | Плюс | Цена / причина отклонения для MVP |
|---|---|---|
| FFmpeg внутри HTTP API | Минимум процессов | Долгие задачи влияют на HTTP и восстановление |
| Worker пишет в общую БД | Меньше внутренних HTTP-вызовов | Неясное владение данными и сильная связность |
| Только RabbitMQ ack без SQL job | Проще очередь | Труднее восстановить пропущенный result и контролировать попытки |
| Public bucket | Простой player | Не выполняет PRIVATE |
| Подписать только master | Маленькая реализация | Не защищает обычные ссылки сегментов |
| Delivery gateway / CDN signed cookies | Единая защита путей и эффективный кэш | Дополнительная инфраструктура; рассмотреть при росте |

## Последствия

API принимает маленькие playlist requests; потребуется корректный parser URI. Старые segment URL действуют до TTL. Lease требует heartbeat, абсолютного timeout и recovery scheduler. SQL/S3/broker не образуют общую транзакцию; orphan cleanup обязателен.

Перед реализацией выбрать S3-совместимое хранилище с multipart, CORS и scoped temporary credentials. Не утверждать поддержку этих возможностей произвольным провайдером без проверки его документации.

## Подтверждение

Испытать повтор messages, два worker, смерть worker, S3-success/SQL-failure, приватный HLS, удаление во время обработки и отсутствие секретов в logs. Под нагрузкой измерить overhead переписывания плейлистов; при росте пересмотреть delivery gateway.
